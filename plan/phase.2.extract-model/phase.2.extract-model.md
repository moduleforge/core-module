# Phase 2 — Extract model

## Goal
Move migrations 0000–0005 and their matching sqlc queries from `users-module/model` into `core-module/model`. Generate `core-module/model/db/`. No changes to users-module yet — that's Phase 3.

## Inputs
Source files under `users-module/model/`:
- `migrations/0000_helpers.sql`
- `migrations/0001_entities.sql`
- `migrations/0002_legal_entities.sql`
- `migrations/0003_natural_persons.sql`
- `migrations/0004_corporations.sql`
- `migrations/0005_service_accounts.sql`
- `queries/entities.sql`
- `queries/legal_entities.sql`
- `queries/natural_persons.sql`
- `queries/corporations.sql`
- `queries/service_accounts.sql`

## Outputs
- Same files copied (not moved yet) into `core-module/model/`.
- `core-module/model/db/*.go` generated by sqlc.
- `core-module/model/migrations/atlas.sum` sealed.

## Hard rules
- **Copy, don't move** in this phase. users-module must stay buildable until Phase 3.
- Do not alter SQL content during copy — verbatim.
- sqlc output package name is `db` (matches users-module convention).

## Tasks
- 2.1 Copy SQL files into core-module/model
- 2.2 Run sqlc build
- 2.3 Run atlas migrate hash
- 2.4 Compile-check

## How to verify
- `cd core-module/model && make build` → sqlc generates without errors.
- `go build ./...` in core-module/model → clean.
- `atlas migrate validate` and `atlas migrate hash` succeed.
- `diff users-module/model/migrations/000{0..5}_*.sql core-module/model/migrations/` → identical.

## Notes
- Phase 3 will delete the originals in users-module/model and set up the compose pipeline. Until then there's temporary duplication — acceptable.
